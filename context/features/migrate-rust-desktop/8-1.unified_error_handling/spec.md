# 统一错误处理

## 业务目标

统一 Web API、Rust Commands、前端 services 和 UI 的错误结构，使 Web 与 Desktop 在异常场景下有一致、可理解、可恢复的用户体验。

## 使用场景

### 数据库连接失败

Desktop 用户数据库配置错误或网络断开时，页面显示明确提示，不出现白屏。

### 表单校验失败

用户提交缺少标题、非法字段或重复名称时，Web 与 Desktop 都显示相同语义的错误。

### 文件操作失败

文件过大、读取失败、写入失败、打开失败时，用户看到具体原因和可操作提示。

## 错误码

统一错误码：

| 错误码 | 说明 |
| ------ | ---- |
| `DB_CONNECTION_FAILED` | 数据库连接失败 |
| `VALIDATION_ERROR` | 请求参数或表单校验失败 |
| `NOT_FOUND` | 数据不存在 |
| `PERMISSION_DENIED` | 权限不足 |
| `FILE_TOO_LARGE` | 文件超过限制 |
| `FILE_READ_FAILED` | 文件读取失败 |
| `FILE_WRITE_FAILED` | 文件写入失败 |
| `FILE_OPEN_FAILED` | 文件打开失败 |
| `DUPLICATE_NAME` | 名称重复 |
| `UNKNOWN_ERROR` | 未知错误 |

## 错误展示规则

1. 用户可修正的问题显示在当前表单或操作区域。
2. 全局服务不可用显示页面级错误或顶部提示。
3. 删除、导出、打开等动作失败使用 toast 或局部错误。
4. 错误消息不暴露数据库密码、完整连接串或本地敏感路径。

## 验收标准

1. Web 和 Desktop 错误展示一致。
2. 数据库连接失败提示清楚。
3. 文件过大提示清楚。
4. 未找到数据提示清楚。
5. 未知错误不会导致页面白屏。
6. services 能把 Web 和 Rust 的错误转换为统一前端错误类型。
