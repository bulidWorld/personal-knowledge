# 统一错误处理 — UI 设计

## 错误层级

| 层级 | 使用场景 | 展示方式 |
| ---- | -------- | -------- |
| 字段级 | 表单字段校验失败 | 字段下方错误文案 |
| 操作级 | 保存、删除、上传失败 | toast 或操作区提示 |
| 页面级 | 数据加载失败 | 页面空状态/错误状态 |
| 全局级 | 数据库断开、配置缺失 | 顶部横幅或设置入口提示 |

## 文案原则

1. 告诉用户发生了什么。
2. 尽量告诉用户下一步可以做什么。
3. 不展示数据库密码、连接串、堆栈信息。
4. 同一错误码在 Web 与 Desktop 中使用一致文案。

## 示例

| 错误码 | 推荐文案 |
| ------ | -------- |
| `DB_CONNECTION_FAILED` | 无法连接数据库，请检查网络和数据库配置。 |
| `VALIDATION_ERROR` | 请检查填写内容后再保存。 |
| `NOT_FOUND` | 这条数据不存在，可能已被删除。 |
| `FILE_TOO_LARGE` | 文件超过大小限制，请选择更小的文件。 |
| `FILE_OPEN_FAILED` | 无法打开文件，请检查本机默认打开程序。 |

## 交互细节

1. 保存失败后保留用户输入。
2. 上传失败后保留当前知识内容。
3. 数据加载失败提供重试按钮。
4. 数据库未配置时提供进入设置页的入口。
